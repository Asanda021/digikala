## بخش اول: آزمون‌های کد

- ۲۱ فایل PHP در کنترل واژگانی مستقل، با درنظرگرفتن چندبخشی بودن PHP/HTML، از نظر رشته‌ها، نظرها، پرانتزها، براکت‌ها و آکولادها بررسی شدند. ۲۱/۲۱ بدون مشکل در این کنترل.
- ۲ فایل JavaScript قالب با تحلیل‌گر JavaScript داخلی V8 بررسی شدند. ۲/۲ بدون ایراد نحوی.
- اسکریپت جدید scripts/security-compat-check.mjs از نظر نحو بدنه برنامه بررسی شد و برای اجرای مستقل Node.js تهیه شده است.
- ۹ قرارداد امنیت/سازگاری در کد شاخه اصلاحی بررسی شد: ۹/۹ برقرار.
- قبلاً در همین نوبت فرایند، آزمون شبیه‌سازی تعاملات JavaScript شامل حد مقایسه/علاقه‌مندی، افزودن و حذف و کارکرد در نبود ذخیره‌سازی مرورگر بررسی شده‌اند. این‌ها تست مرورگر و ووکامرس واقعی نیستند.
- ZIP کاندیدای ۳۰ فایلی بازتولید و هر ۳۰ CRC-32 و فهرست مرکزی ZIP دوباره کنترل شد.

## بخش دوم: ایرادهای پیدا و اصلاح‌شده

۱. **فیلتر قیمت:** استفاده مستقیم از متادیتای _price برای محدوده قیمت محصولات متغیر دقیق نبود. ورودی‌های فیلتر به min_price و max_price استاندارد WooCommerce تغییر کرد تا WC_Query از جدول lookup و قواعد مالیات خودش استفاده کند.

۲. **ویژگی محصول متغیر و حریم اطلاعات:** ویژگی‌های Variation می‌توانند رشته ساده باشند. استفاده از get_visible بدون بررسی کلاس امکان خطای Fatal روی درخواست دستکاری‌شده داشت. بررسی WC_Product_Attribute اضافه شد و شناسه محصول Variation از endpoint عمومیِ مجموعه‌ها کنار گذاشته شد.

۳. **درخواست‌های شناسه تودرتو:** داده غیر اسکالر پیش از absint رد می‌شود تا ورودی آرایه‌ای تبدیل تصادفی به شناسه کالا نشود.

۴. **ترکیب فیلتر تخفیف:** شناسه صفر (علامت مجموعه بی‌نتیجه در WP_Query) به‌اشتباه با array_filter حذف می‌شد. اصلاح شد.

۵. **دریافت فهرست کالا:** نمایش محصولات صفحه نخست از WP_Query مستقیم به API عمومی wc_get_products منتقل شد؛ وضعیت انتشار و قابلیت نمایش دوباره بررسی شده و context محصول و حلقه پس از رندر بازگردانده می‌شود.

۶. **کش پیگیری سفارش:** فرم پیگیری مهمان با شناسه bn_view=track به خروجی‌های منع کش عمومی افزوده شد.

## آزمون‌هایی که هنوز نباید PASS تلقی شوند

- اجرای واقعی php -l روی نسخه remote PHP: با وجود آماده بودن PHP CLI در محیط Chat، انتقال مستقیم فایل‌های GitHub به محیط اجرایی به دلیل محدودیت شبکه انجام نشد؛ کنترل واژگانی جانشین php -l نیست.
- اجرای مستقیم اسکریپت scripts/security-compat-check.mjs در check-out مخزن؛ نحو و قراردادها به‌صورت مستقل در این گفتگو ارزیابی شد.
- بوت وردپرس و ووکامرس، تست افزونه‌ها، محصولات متغیر با variation واقعی، کوپن، مالیات و ارسال.
- هر دو مسیر تسویه‌حساب Classic و Checkout Blocks. hookهای کلاسیک بر پایه مستندات رسمی روی بلوک‌ها یکسان کار نمی‌کنند.
- تست نفوذ واقعی، HTTP rate limiting، صفحه‌آرایی فارسی و مرورگر، Core Web Vitals و پرداخت آزمایشی.
